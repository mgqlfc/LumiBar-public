# Mac 分支的具体差异

只读对照基准：`codex/macos-port` 的 `35f9f23f337bc4835bcd3a3e2729157cb63dcef1`。Mac 本地后续改动继续保留；先检查当前代码是否已经处理这些项，再修改。

| 部位 | 该提交的实现 | 目标与参考 |
|---|---|---|
| 天气胶囊 | App.swift:172–204 用 NSStatusBarButton 的图片+文字；主图标19，温度用系统等宽13，降水用 emoji 水滴9；缺独立胶囊玻璃与天气背景光 | 自定义内容视图绘制胶囊；同一图集的小降水图标、Geist、按文字测量；参考 weather-capsule / wide / lite 图片 |
| 天气浮窗圆角 | WeatherView.swift:144 固定29，系统 regular glass同时决定整体形状 | 主表面12、阴影边距16；材质与几何分开 |
| 当前温度 | WeatherView.swift:241–258 圆体51、体感单独一行，当前温度只有度数 | Geist 52，`8°C`；“最低、最高、体感”同排 |
| 悬停天气 | WeatherView.swift:98–113 复用大号current、完整降水趋势与一行AQI | 单行头部 + 居中三等栏，264×160；不塞详情区块 |
| 标题和来源 | WeatherView.swift:150、427–432 标题带地区副标题，天气源/更新时间放底部 | 同排城市、来源、“上次更新：”，省掉底部常驻来源 |
| 底部指标 | WeatherView.swift:400–424 3×2左对齐网格，单位混在数字行，增加PM指标 | 一排五等栏、居中，单位在标题，小号风向；额外PM放详情，不改变主布局 |
| 24小时 | WeatherView.swift:335 起使用 Charts 轴，再单独排图标 | 同一坐标模型驱动温度标签、节点、图标与时间 |
| 歌词窗口 | App.swift:344 起歌词高度370、宽478 | 先按420×650主体对齐；Mac可用空间不足再缩高，保留排布规则 |
| 歌词排布 | MusicView.swift:215–235 只构造当前前一行到后两行，当前25/其他16、普通行强制一行 | 全文排布同一设置字号、正常换行、按实际字高聚焦和渐隐；参考 music-light/dark |
| 歌词遮罩 | MusicView.swift:231–234 固定12%/84% | 使用动态焦点安全区和长上下渐隐；高亮整行保持清楚 |
| 设置页 | App.swift 里的紧凑配置视图 | 与560×650外观页截图对照侧栏、九色强调色、字体设置和选择态 |

Windows 样例源代码、Mac 当前代码都在仓库。首轮按“字体与字号 → 栅格与间距 → 图标与圆角 → 图层 → 材质 → 动画 → 真实数据”的顺序核对。平台原生材质只负责背景效果，不自行改掉几何和信息层次。

Mac 音乐岛位置与收起轮廓继续沿用刘海方案，本清单不要求把任务栏的音乐胶囊原样搬到刘海。音乐详情与歌词仍遵循本包。
